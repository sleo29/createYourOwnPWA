# Inventory Management PWA Template

A reusable, static-first inventory application template. The `.hbs` pages are compiled by Handlebars and the generated pages use vanilla CSS and ES modules. Demo records and configuration overrides are stored in the browser's `localStorage`; no backend, account, or third-party runtime dependency is required.

## Run the standalone demo

1. Use Node.js 18 or newer.
2. From the repository root, install Handlebars as a development-only tool if it is not already available:

   ```sh
   npm install --no-save --package-lock=false handlebars
   ```

3. Compile the pages and static files using the example script:

   ```sh
   node templates/inventory/scripts/build-demo.mjs
   ```

4. Serve the generated `templates/inventory/demo-dist` directory over HTTP on `localhost` (service workers do not work from `file://`). For example:

   ```sh
   python3 -m http.server 8000 --directory templates/inventory/demo-dist
   ```

5. Open the URL printed by the static server. Use the dashboard navigation to manage products, categories, movements, reports, and settings. Data is persisted in the browser for the current origin. The service worker caches only the static app shell and never caches API responses.

The demo build output is disposable and intentionally not part of the template. For an application generated by your platform, compile the pages and copy the static assets into the same URL structure instead.

## Handlebars integration

Register every `.hbs` file in `partials/` as a named Handlebars partial before compiling a page. Compile each `pages/*.hbs` page with the same configuration object and provide `pageScript` as the page module name (`dashboard`, `products`, `categories`, `stock`, `reports`, or `settings`). The template expects the compiled entry page at `/index.html`; its other page links use the matching `.html` names.

The required placeholder details and integration notes are documented in [PLACEHOLDERS.md](./PLACEHOLDERS.md). The schema fields and generated template metadata are in `schema.json` and `template.json`.

The standard Handlebars `if` block is used only to conditionally include the page-specific module in `partials/footer.hbs`. There are no custom helpers or inline Handlebars expressions in JavaScript or CSS.

## Template contents

- `pages/` contains the six complete app pages.
- `partials/` contains the shared app shell and reusable product, category, and movement dialogs.
- `assets/js/data.js` is the local data adapter and demo seed source. Replace its storage operations with API calls when connecting a backend.
- `assets/js/` contains shared UI behavior and page-specific modules.
- `assets/css/style.css` contains the responsive light-theme design.
- `manifest.template.json` and `sw.template.js` define installability and versioned app-shell caching.
- `icons/` contains scalable placeholder application icons colored from `primaryColor`.

## Local data behavior

The first visit seeds neutral sample categories, products, and stock movements. Product/category/movement changes persist under `inventory-pwa-demo-v1` in local storage. Product quantity changes made in the product form also create a stock movement; category deletion is blocked while products still belong to that category. Stock-out and adjustment operations cannot reduce stock below zero. Settings are persisted separately and can be saved from the Settings page.

Local browser storage is a demo adapter, not a multi-user database. It is not synchronized or backed up. For production integration, replace the methods in `assets/js/data.js` while keeping the page modules' data contracts.
